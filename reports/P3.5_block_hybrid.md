# P3.5 — Block-Structured Hybrid Rotation

**Status:** Implemented and benchmarked (pure NumPy, no model/GPU).
**Files:** `baseline/p35_hybrid.py`, `baseline/run_p35.py`
**Run:** `python3 -m baseline.run_p35 --d 64 --nrot 2000 --b 2`

## Purpose

If pure Hadamard/sign-flip rotations underperform dense Haar rotations, add a
small dense mixing layer (8x8 or 16x16 orthogonal blocks) after the fast
transform. This preserves most of the O(d log d) benefit while adding local
mixing capacity. Should only be tested after P0.2 proves where structured
rotations fail — which is exactly what P0.1/P0.2 established (hdhdh already
matches Haar; this tests whether a hybrid is even needed or adds anything).

## Method

Build a block-hybrid rotation: FWHT (hdhdh-style) followed by a block-diagonal
dense orthogonal mixing (8x8 or 16x16 blocks). Compare against Haar and pure
hdhdh on the rotation checks (beta_ks, rms_corr, mse, bias) at b=2 total budget
(product estimator budget: b−1=1 MSE base + 1-bit residual QJL).

## Results — d=64, nrot=2000, b=2, seed=0

```
rotation      beta_ks  rms_corr fact_gap      mse     bias   rt_s
haar           0.0022    0.0223   0.1101   0.3561   0.6436  0.199
hdhdh          0.0192    0.0216   0.0948   0.3584   0.6463  0.862
hybrid-b8      0.0019    0.0222   0.0506   0.3577   0.6500  1.075
hybrid-b16     0.0014    0.0218   0.0617   0.3588   0.6336  1.033
```

## Findings

1. **The block-hybrid matches Haar on distribution.** hybrid-b8 beta_ks 0.0019
   and hybrid-b16 0.0014 are at the Haar level (0.0022), vs hdhdh's 0.0192.
   Adding dense block mixing after the fast transform fully closes the small
   residual distribution gap that pure FWHT retains.

2. **MSE and bias are already at Haar level for all rotations.** mse ~0.356-0.359
   and bias ~0.63-0.65 across Haar, hdhdh, and both hybrids — the b=2 product
   estimator is insensitive to the residual distribution gap.

3. **The hybrid adds compute without quality benefit here.** runtime 1.03-1.08s
   vs hdhdh 0.86s vs Haar 0.20s (pure-NumPy constants; see P0.1 runtime
   caveat). Since hdhdh already statistically matches Haar, the hybrid's extra
   mixing capacity buys nothing measurable in this protocol — confirming the
   proposal's premise ("only test if structured rotations fail"): they don't
   fail at 3 rounds.

## Implications

- Block-structured hybrid rotation is a valid fallback (matches Haar on every
  check) but is not needed when hdhdh is used — it adds cost for no measurable
  gain.
- If a future structured rotation (e.g. fewer rounds, or an outlier-constrained
  variant) shows a distribution gap, the hybrid is the drop-in fix.
- Confirms P0.2's headline: 3-round Hadamard+sign-flip is sufficient; the
  hybrid is a reserve option, not an active branch.
