# P2.8 — OCTOPUS-Style Triplet Direction + Norm Codec

**Status:** Implemented and benchmarked (pure NumPy, no model/GPU).
**Files:** `baseline/p28_octopus.py`, `baseline/run_p28.py`
**Run:** `python3 -m baseline.run_p28 --d 64 --nrot 2000`

## Purpose

Test a small-block codec after rotation: normalize the vector, split rotated
coordinates into contiguous triplets, store each triplet's norm, map each
triplet direction on S² to two octahedral coordinates, and Lloyd-Max quantize
the norm and the two direction coordinates with non-uniform bit allocation.
Grounded in OCTOPUS: triplet-wise octahedral direction quantization is claimed
to improve rotation-preconditioned KV codecs at b=2 and b=3.

## Method

Triplet codec: contiguous triplets (21 at d=64, 1 leftover coordinate
scalar-quantized at b bits), scalar norm + octahedral (S²) direction mapped to
two coordinates, Lloyd-Max quantized with non-uniform bit allocation. Codebooks:
empirical 1-D k-means over calibration samples from the exact protocol
distribution; octahedral round-trip verified to machine precision (~1.9e-16).
Matched total bits: b_norm + 2·b_dir == 3·b per triplet (plus b·rem leftover),
exactly b·d — the same as the scalar reference.

## Results — d=64, nrot=2000, ncal=1000, seed=0

```
b=1  (budget 64 bits; scalar Lloyd-Max MSE = 0.3587)
  b_norm b_dir bits/trip       MSE   ratio
       1     1         3    0.6043   1.685
  best split: b_norm=1 b_dir=1 -> MSE 0.6043 (1.68x scalar)

b=2  (budget 128 bits; scalar Lloyd-Max MSE = 0.1140)
  b_norm b_dir bits/trip       MSE   ratio
       2     2         6    0.1658   1.454
       4     1         6    0.5831   5.115
  best split: b_norm=2 b_dir=2 -> MSE 0.1658 (1.45x scalar)

b=3  (budget 192 bits; scalar Lloyd-Max MSE = 0.0336)
  b_norm b_dir bits/trip       MSE   ratio
       1     4         9    0.0596   1.770
       3     3         9    0.0439   1.305
       5     2         9    0.1511   4.491
       7     1         9    0.5766  17.137
  best split: b_norm=3 b_dir=3 -> MSE 0.0439 (1.31x scalar)
```

## Findings

1. **The triplet codec LOSES to scalar Lloyd-Max at every matched budget**
   (best ratio 1.31x at b=3, worse at lower bits: 1.68x at b=1). A clear
   negative result for the statistical setup: after a Haar rotation, coordinates
   are already near-independent with the exact-Beta marginal, so exploiting
   local 3D geometry via octahedral direction coding does NOT beat independent
   scalar quantization at the same bit count.

2. **The balanced split (b_norm == b_dir) is best.** Starving either the norm
   (b_norm=1, b_dir=4: 1.77x) or the direction (b_norm=7, b_dir=1: 17x) collapses
   MSE. The norm carries the magnitude information and cannot be underfunded.

3. **Why it loses:** the triplet uses 3 scalar code slots for 3 degrees of
   freedom; scalar Lloyd-Max uses the same slots independently, each matched to
   the exact 1-D marginal. The octahedral mapping's joint-handling benefit does
   not compensate for the loss of independent marginal matching — the scalar
   path is already near-optimal on the Beta marginals (paper Theorem 1).

## Implications

- OCTOPUS-style triplet coding (P2.8) is **not competitive with scalar
  TurboQuant at matched bits** in this statistical protocol. This is the kind of
  negative result the backlog wants early: scalar TurboQuant is the stronger
  baseline on rotation-preconditioned, near-independent coordinates.
- The OCTOPUS gains reported in the literature may depend on un-rotated or
  differently-preconditioned distributions (where coordinates are NOT
  independent, so joint coding helps) or on real KV statistics with covariance.
  Testing that requires real KV tensors (P0.4, GPU box).
- P2.9 (joint rounding) can partially repair the triplet codec, but starting
  from a worse codec limits the ceiling; the scalar baseline remains the
  stronger default.
