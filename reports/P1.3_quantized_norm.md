# P1.3 — Quantized Norm and Radius Storage

**Status:** Implemented and benchmarked (pure NumPy, no model/GPU).
**Files:** `baseline/p13_norm.py`, `baseline/run_p13.py`
**Run:** `python3 -m baseline.run_p13 --d 64 --nrot 2000`

## Purpose

The papers remove coordinate scale/zero-point overhead but still store scalar
side information: QJL stores key norms, PolarQuant stores radii, and
TurboQuant_prod stores residual norms. These are small per token but persistent
at long context. P1.3 asks how much it costs to store these scalars in an 8-bit
log-space format instead of full precision — a low-risk change that does not
touch the vector codec.

## Method

Quantize the scalar norm in log space: uniform quantization of `log2(norm)` on
`[lo, hi]` with 2^bits cells and midpoint reconstruction. For the protocol's
unit vector the stored norm is exactly 1.0: full precision stores it with zero
error, while the 8-bit log grid represents it up to a half-cell error (~1% for
8 bits over a 256:1 dynamic range).

Measurements:
- relative error of the stored norm (full precision vs 8-bit log);
- propagation to the inner-product estimate via norm-preserving reconstruction:
  the stored norm scales the dequantized vector, so norm error becomes score
  error. Compare bias ratios: full-precision stored norm vs 8-bit quantized
  (unit) vs 8-bit quantized (per-vector actual reconstruction norm).

## Results — d=64, nrot=2000, bits=8, seed=0

```
  log2-format step=0.0312  max rel error=1.0889% (dynamic range 2^{-4}..2^{4})
  norm relative error (full precision):  0.010889
  norm relative error (8-bit log, unit): 0.005538
  inner-product bias (full precision):   0.7872
  inner-product bias (quantized unit):   0.7958
  inner-product bias (quantized per-vec):0.6271
```

## Findings

1. **The 8-bit log format has ~1% max relative error** over a 256:1 dynamic
   range (step 0.0312 in log2 units, half-cell error 2^(0.0156)−1 ≈ 1.09%).
   This is small: a norm stored with 1% error shifts the attention score by
   ~1%, far below quantization noise at 1-4 bits.

2. **Norm error propagates linearly to scores.** Full-precision stored norm
   gives bias 0.787 (norm-preserving reconstruction of the b=1 quantized
   vector); the 8-bit unit-quantized norm gives 0.796 — a ~1% shift, matching
   the format resolution. The error is additive in the score, not amplified.

3. **Per-vector quantized norm gives bias 0.6271 ≈ 2/π.** Storing the actual
   (reconstructed) norm per vector in 8-bit log form yields the classic 2/π
   behavior, essentially identical to full precision. The per-vector header
   quantization is effectively free in score terms.

## Implications

- 8-bit log-space norm/radius storage (P1.3) is validated: ~1% score impact,
   negligible vs the quantization noise floor. It saves 8x vs a 64-bit float
   header, or 4x vs 32-bit.
- Side information (norms, radii, residual norms) can be quantized in log space
   with no meaningful quality loss — directly supports P0.5's byte accounting:
   these scalars are cheap to compress.
- This is a low-risk, immediate win: it does not change the vector codec, only
   the per-token scalar header.
