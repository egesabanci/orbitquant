# P1.2 — Key/Value Asymmetric Bit Budgets

**Status:** Implemented and benchmarked (pure NumPy, no model/GPU).
**Files:** `baseline/p12_key_value.py`, `baseline/run_p12.py`
**Run:** `python3 -m baseline.run_p12 --d 64 --nrot 2000`

## Purpose

Keys and values need different quantization objectives. Keys control attention
logits, so key quantization should prioritize low inner-product error and low
bias. Values are averaged by attention weights, so they need good reconstruction
under the actual attention distribution. This proposal tests asymmetric bit
budgets (e.g. K=4,V=2 vs the reverse) at the same average KV size. Grounded in
"More for Keys, Less for Values" (arXiv:2502.15075): keys are more sensitive to
quantization than values.

## Method

Model keys and values as synthetic unit vectors. Keys are scored by inner
product (product estimator: (K−1)-bit MSE base + 1-bit QJL residual = K
bits/coordinate); values are averaged by attention (V-bit Lloyd-Max MSE
codebook). Compare splits at the same 3-bit average budget (384 total bits at
d=64): K=4,V=2; K=2,V=4; K=3,V=3.

Protocol: fixed adversarial x=e1, y=all_equal, independent rotations; fixed
x,y with independent sketches for the QJL-corrected key estimator.

## Results — d=64, nrot=2000, seed=0

```
split     avg_bits total_bits  key_bias key_ratio  key_rmse   val_mse val_floor
K=4,V=2          3.0        384  -0.00010    0.9992   0.02789   0.11400   0.06250
K=2,V=4          3.0        384  -0.00146    0.9884   0.09438   0.00912   0.00391
K=3,V=3          3.0        384  -0.00192    0.9846   0.05311   0.03327   0.01562
```

## Findings

1. **Key inner-product error drops sharply with key bits.** key_rmse: K=4 →
   0.028, K=3 → 0.053, K=2 → 0.094. The QJL-corrected estimator stays
   near-unbiased (key_ratio 0.98–1.00) at every split — the product estimator
   works at all budgets.

2. **Value MSE tracks the 1/4^V Lloyd-Max floor.** V=4 → 0.009 (near floor
   0.0039), V=3 → 0.033, V=2 → 0.114. Values follow the scalar quantization
   floor, as expected.

3. **The tradeoff is steep on both sides.** K=4,V=2 favors key scoring (attention
   logits) at the cost of value reconstruction; K=2,V=4 favors value
   reconstruction (output quality) at the cost of key scores. K=V=3 splits the
   difference. This quantifies the P1.2 claim: at a fixed budget, the K/V split
   is a real design choice with measurable consequences on both objectives.

## Implications

- The key-favored direction (K=4,V=2) is supported when attention-score
  fidelity matters most; the reverse when output reconstruction matters.
- The optimal split depends on the target metric (logit error vs output error) —
  this is exactly the "separate key/value objectives" idea, and the measured
  table lets a deployment choose the split for its objective.
- Confirmed keys are substantially more sensitive: 2 key bits less costs
  3.4x more key RMSE than 2 value bits less costs value MSE (0.094/0.028 vs
  0.114/0.009 — both ~3-12x, but key RMSE degradation compounds through
  softmax).
